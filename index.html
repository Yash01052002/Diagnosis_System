01

Quick Start — Windows

Recommended path for reproducing the local development environment.

Before you begin: BlackBox is a local development/demo system. Do not commit your real API keys, JWTs, or other secrets to GitHub.
1

Install Docker Desktop

Docker Desktop provides the container runtime used by BlackBox.

Install Docker Desktop for Windows, start it, and make sure the Linux/WSL 2 backend is available.

Docker Windows installation ↗WSL 2 backend ↗
docker --version
docker compose version
2

Install Ollama

BlackBox can use local AI instead of a paid cloud API.

Install Ollama for Windows, then open PowerShell:

Ollama for Windows ↗
ollama --version
ollama pull llama3.1
ollama list
3

Clone BlackBox

Replace the repository URL below with your GitHub repository URL.

git clone YOUR_GITHUB_REPOSITORY_URL
cd YOUR_REPOSITORY_FOLDER
4

Create your environment file

Start from .env.example and keep secrets local.

Copy-Item .env.example .env
notepad .env

For the local Ollama configuration, use:

LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_CHAT_MODEL=llama3.1
LLM_TIMEOUT_SECONDS=120
Important: Inside the Docker container, localhost:11434 points to the container. On Docker Desktop for Windows, use host.docker.internal:11434 to reach Ollama running on Windows.
5

Start the stack

Build and start the services defined by your compose file.

docker compose up -d --build
docker compose ps
6

Verify the backend

Open the health endpoint and API documentation.

http://localhost:8000/health http://localhost:8000/docs http://localhost:3000 
docker ps
docker logs blackbox-backend --tail 100
02

How BlackBox works

The complete diagnosis pipeline.

Crash report
→
Crash ingestion
→
ELF symbolication
→
RAG retrieval
→
Ollama / Llama 3.1
→
Diagnosis + fix

Crash ingestion

Receives fault metadata, registers, stack data, firmware/build identifiers, and task information.

Symbolication

Uses the indexed ELF/debug symbols to map addresses such as PC and LR to functions and source lines.

RAG

Retrieves relevant STM32/FreeRTOS engineering references from the knowledge base.

Local AI

Llama 3.1 analyzes the crash context and retrieved material without requiring OpenAI API credits.

03

Run the first fault test

Use a deliberately faulty ELF to validate symbolication and diagnosis.

1

Build the test ELF

Example using the ARM GNU toolchain.

arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -nostdlib `
  "-Wl,-T,linker.ld,-Map=build\null_pointer.map" `
  "-Wl,--gc-sections" `
  build\null_pointer.o -o build\null_pointer.elf

arm-none-eabi-nm -n build\null_pointer.elf
2

Upload the ELF

Use Swagger's POST /api/v1/builds endpoint with your JWT.

curl.exe -X POST "http://localhost:8000/api/v1/builds" `
  -H "Authorization: Bearer $token" `
  -F "file=@C:\path\to\build\null_pointer.elf" `
  -F "firmware_version=1.5.0-null-pointer" `
  -F "build_version=null-pointer-test-001" `
  -F "hardware_model=STM32F407VG" `
  -F "notes=BlackBox NULL pointer test"
3

Submit a crash

Register a device first, then submit the crash report with the device API key as required by your API.

Use the Swagger documentation at http://localhost:8000/docs so the exact request schema stays synchronized with the backend.

4

Symbolicate and diagnose

The expected result for the supplied NULL-pointer test is a function/source mapping similar to:

PC → NullPointerFault
File → null_pointer.c
Line → 6
LR → SensorTask+0x8

AI → NULL pointer dereference in SensorTask

Troubleshooting

Common issues from the local Windows setup.

Docker API / daemon is not running

Start Docker Desktop and verify the Docker context with docker info. If Docker Desktop is using WSL 2, verify WSL is installed and updated.

Ollama works from Windows but BlackBox cannot connect

Check OLLAMA_BASE_URL inside the backend container. For Ollama running on Windows, use http://host.docker.internal:11434, not http://localhost:11434.

docker exec blackbox-backend printenv OLLAMA_BASE_URL
docker exec blackbox-backend python -c "import urllib.request; print(urllib.request.urlopen('http://host.docker.internal:11434/api/tags').read().decode())"
401 invalid_token

Authorize Swagger with a current JWT under the HTTP Bearer security scheme. Do not paste an expired/revoked token. The exact security scheme names can vary with the generated API docs.

OpenAI 429 / no API credits

Use the local Ollama configuration above. BlackBox does not need OpenAI API credits for the local Llama 3.1 path.

ELF says indexed but symbolication fails

Confirm the crash's build_version exactly matches the indexed firmware build and that the uploaded ELF contains the debug information/symbols needed by your symbolicator.

05

Security checklist

  • Never commit .env or real API keys.
  • Use .env.example for safe, non-secret configuration examples.
  • Use fresh JWTs for local testing and never publish them.
  • For production, add proper secret management, HTTPS, access controls, backups, rate limits, and monitoring.
